# 面向多资产配置的大语言模型风险反馈与自适应决策研究

# 第二阶段开发分工与接口规范

**版本：V1.0**\
**日期：2026年11月24日**\
**阶段：第二阶段------基础模块开发**

## 一、阶段目标

第一阶段已完成研究方案、数据口径、模型决策机制、风险反馈机制及回测实验设计的统一。第二阶段进入基础模块开发阶段，任务是将既定研究方法转化为可独立运行、可验证、可复现的
Python 程序。

本阶段采用五人并行开发方式。每位成员负责相对独立的功能模块，统一遵循项目目录、数据规范和接口协议。

主要目标： 1. 完成五个核心模块的基础程序开发。 2. 统一模块输入输出结构。
3. 完成各模块独立测试。 4. 建立统一代码管理和版本协作机制。 5.
为第三阶段模块整合与风险反馈闭环搭建做好准备。

本阶段不要求完成全部四组实验的完整历史回测。

## 二、团队人员与职责分工

### 1号：大模型决策模块及项目总体协调

负责目录：`llm_decision/`

主要工作： 1. 接入 DeepSeek 官方 API，主实验使用 DeepSeek V4.1 Flash。
2. 建立模型输入接口，接收市场特征及相应实验组允许使用的反馈信息。 3.
编写并管理统一 Prompt。 4. 生成三类资产的目标风险预算。 5. 完成模型返回
JSON 的解析、字段检查和预算合法性校验。 6.
实现模型调用记录、失败重试及预算回退机制。 7.
负责公共接口协调、代码整合和阶段验收。

职责边界： - 大语言模型：市场信息理解、风险判断、风险预算生成。 -
Python：数据处理、预算校验、预算平滑、权重求解、成交和回测。

模型输出风险预算（risk budget），不是实际资金权重（portfolio weights）。

交付成果：API 调用程序、Prompt 文件、模型输入输出接口、JSON
校验程序、调用日志与异常处理程序、独立测试样例及运行说明。

### 2号：数据处理模块

负责目录：`data_processing/`

主要工作： 1. 读取第一阶段冻结的统一日收益率矩阵。 2.
检查日期、资产代码、收益率和数据完整性。 3.
建立按历史截止日期提取数据的程序。 4.
计算三类资产的20日、60日累计收益特征。 5.
计算20日、60日、250日年化波动率。 6. 计算60日、250日滚动资产相关矩阵。
7. 处理滚动窗口不足、日期缺失和异常数据情况。

交付成果：数据读取程序、数据质量检查程序、市场特征计算程序、滚动窗口数据提取接口、测试报告及运行说明。

数据处理必须严格遵循第一阶段统一矩阵，不得自行更换数据源或重新计算替代收益矩阵。

### 3号：传统量化策略模块

负责目录：`baseline_strategies/`

主要工作：实现三种传统组合配置策略： 1. 等权策略（Equal Weight）。 2.
最小方差策略（Minimum Variance）。 3. 风险平价策略（Risk Parity）。

具体要求： - 等权策略：每种资产配置1/3，每月恢复目标权重。 -
最小方差策略：在统一可行域内最小化组合方差。 -
风险平价策略：使三类资产的风险贡献占比尽可能接近1/3。 -
三种策略使用统一资产池、交易规则、成本及评价起点。 -
主实验统一采用250日窗口；500日求解窗口属于单独的稳健性实验。 -
最大夏普策略仅用于敏感性分析，不纳入三种主要基准。

交付成果：三种策略的独立 Python
程序、目标权重输出、风险贡献计算与检查结果、权重约束验证、测试样例及运行说明。

### 4号：风险计算与风险归因模块

负责目录：`risk_metrics/`

主要工作分为三个部分。

**（1）组合风险指标** - 20日、60日组合收益。 - 20日、60日组合波动率。 -
当前回撤。 - 最大回撤。 - CVaR（95%）。

**（2）风险预警** - 回撤预警。 - 波动率预警。 - 股债相关性预警。

预警规则严格按照《第一阶段最终实验设计方案》第五节执行。

**（3）风险归因** - 各资产风险贡献（RC）。 - 风险贡献占比。 -
风险预算偏差。 - 当前回撤归因。 - 风险变化归因。 - 风险集中度状态。

D组使用完整风险归因反馈；不得将集中度相关字段提前提供给C组。

交付成果：风险指标计算程序、风险预警程序、风险贡献及归因程序、结构化风险反馈输出、计算结果核验及测试报告。

### 5号：回测引擎模块

负责目录：`backtest_engine/`

主要工作： 1. 建立100万元初始资金的组合账本。 2.
实现资产持仓及每日权重漂移。 3. 实现月末信号生成与次月成交机制。 4.
实现收盘成交及新权重生效规则。 5. 实现买卖双边交易成本计算。 6.
计算每日组合毛收益、净收益和净值。 7.
记录每日持仓、成交金额、费用和换手率。 8. 输出回测结果及账本数据。

主实验采用连续权重收盘估值；100份取整属于单独的可交易性稳健性实验。

交付成果：基础回测引擎、每日净值记录、每日持仓记录、成交与交易成本记录、换手率计算、回测测试报告。

## 四、统一开发规范

### 4.1 开发环境

-   Python：3.11。
-   统一使用项目根目录中的 `requirements.txt`。
-   使用 UTF-8 编码。
-   日期统一采用 `YYYY-MM-DD`。
-   收益率采用小数格式。
-   组合权重采用浮点数。

### 4.2 文件命名

Python 文件使用小写字母与下划线命名，例如
`feature_builder.py`、`risk_metrics.py`、`portfolio_optimizer.py`、`backtest_engine.py`。测试文件以
`test_` 开头。JSON 文件使用明确的业务名称和实验组编号。

### 4.3 程序要求

每个模块必须： 1. 有明确的输入参数。 2. 有明确的输出结构。 3.
可以独立运行。 4. 包含异常处理。 5. 提供独立测试。 6.
提供必要的运行说明。 7. 不依赖其他成员电脑上的绝对路径。

### 4.4 数据安全

-   不得上传 `.env`、API Key 或访问令牌。
-   不得将真实密钥写入 Python、JSON 或日志文件。
-   不得私自修改冻结的研究数据。
-   不得将模拟测试数据当作正式研究结果。

## 五、统一接口与模块交互

### 5.1 市场特征接口

由2号提供，供1号和4号使用。

基础字段： - `as_of_date` - `market_features` - `asset_correlations` -
`data_quality`

市场特征包含各资产20日、60日累计收益，以及20日、60日、250日年化波动率。资产相关矩阵包括60日与250日滚动相关性。

### 5.2 风险反馈接口

由4号提供，供1号使用。

-   A组：不提供反馈。
-   B组：增加组合20日、60日收益反馈。
-   C组：在B组基础上增加组合波动、回撤、CVaR及相应预警。
-   D组：在C组基础上增加风险贡献、预算偏差、回撤归因、风险变化归因及集中度状态。

实验组由Python侧管理，不向模型直接暴露组别标签。

### 5.3 模型决策接口

由1号提供，供权重求解及5号回测模块使用。

统一返回八个字段： - `decision_status` - `as_of_date` - `market_state` -
`risk_budget` - `confidence` - `decision_summary` - `key_evidence` -
`failure_assumption`

风险预算必须对应510300、511010、518880，三个预算均为有限正数，合计为1。

### 5.4 回测账本接口

由5号提供，供4号计算实际风险反馈。

至少记录： - 日期与实验组。 - 期初、成交前和期末净值。 -
毛收益与净收益。 - 交易成本。 - 换手率。 - 各资产收益。 -
实际持仓权重。 - 当日生效风险预算。

具体字段与单位以第一阶段最终实验设计方案附录B为准。

**说明：** 本节为模块间的开发接口约定。当前 `interfaces/data_schema.py`
为初始实现，后续需要根据本规范和第一阶段数据字典逐项核对，不得仅以现有代码字段为准。
